## Verdict

KernelInfra implementation commit
`f46064636e02af58f426fd3360f15fa204c9a67d` and agent-gpu-broker
implementation commit `843debd0f116ec34aad908dd76e89a99e28bc65e`
passed exact-source B200 integration qualification.

This closes the v0.4 deployment gap: Kernel Infra no longer trusts a task
author's statement about the command/environment used to launch a long-running
evaluator. It requires the broker-issued started-job admission receipt, verifies
its canonical digest, re-queries the same active receipt through the broker
socket, checks it against live job/allocation/broker identity, and repeats the
entire verification after the evaluator response.

## Fail-closed controls

1. changing the saved receipt label without recomputing the broker-owned digest
   failed with `broker admission receipt digest disagrees with content`;
2. using the correct live receipt but omitting launch-spec/executable digests
   from `service_identity` failed with
   `service identity does not bind broker admission launch_spec_sha256`.

Both commands returned nonzero, produced no deployment file, and submitted no
FIBServe evaluation.

Unit and exact broker suites separately proved that a launch executable changed
while queued fails before spawn and does not create its marker output.

## Terminal and resource semantics

After evidence capture, stopping the gpu-run client cancelled the service with
exit 130 and reason `client disconnected`. The broker immediately closed active
receipt lookup, reported GPU 2 idle with no queue, and retained admission
digests in the terminal result. Both isolated daemon sockets were removed after
graceful termination.

The production broker was left running. At the final check, unrelated KDA work
held GPU 0 while GPUs 1–3 were idle; no test service or test broker remained.

The same broker implementation was also qualified on A800 GPU 1 through a
bounded natural-completion job. Its live receipt matched during execution,
closed after exit 0, and the production A800 broker returned to GPU 1 idle. See
the broker repository's v0.6 qualification report for those hashes.

## Remaining boundary

The command/environment ownership gap is closed within the trusted Unix-socket
boundary. Files merely referenced by argv—datasets, models, images, configs,
and compatibility assets—are not recursively inferred by the broker and remain
task/evaluator-owned fingerprints. Cross-host global scheduling, hostile
multi-tenancy, priority/preemption, and live-command recovery after broker
restart remain out of scope.
