## Consumer ownership

`service-bind-task` adds the managed deployment id directly to the materialized
service stage. On run acceptance, Kernel Infra snapshots the unique deployment
ids into run state. The service consumer projection is:

```text
all run states
  -> state is nonterminal
  -> deployment id appears in service_deployment_ids
  -> active consumer run ids
```

The projection is recomputed from run ledgers for status, explicit stop, and
idle policy. There is no counter file to drift from accepted/terminal runs.

Server dispatch verifies every referenced managed deployment is ready before
candidate snapshot. Run acceptance and stop/idle transitions contain no await
between the final checks and state mutations, so the daemon event loop
serializes the race.

On normal daemon shutdown and restart recovery, run states become terminal
before service stop/reconciliation, preserving the same ownership rule.

## Remaining boundary

Single-node service reuse now has safe automatic release. The remaining major
infrastructure gap is cross-host routing: an agent still chooses A800 or B200
manually and runs the node-local workflow there. A future dispatcher must route
immutable specs/tasks/candidates while leaving queue/allocation, deployment
history, judge evidence, and frontier authority on each node.
