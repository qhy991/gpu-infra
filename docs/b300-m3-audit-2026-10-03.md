# GPU Infra 架构与 B300-M3 使用审计 — 2026-10-03

## 结论与范围

核心所有权合理：broker 分卡，daemon 管 run/service，evaluator 判正确与计时，
fleet 只做路由和传输。没有证据支持删除 service/fleet 或改掉已有持久 schema。
存在的过度设计主要是把操作与派生视图描述成同等级核心概念、重复的操作手册、
以及跨模块复制的 broker 传输。更严重的问题是发布、安装、部署三者没有闭合。

本轮以远端 `main=e79fd436278ced35ad8bdf5221123f2fb6870856` 为基线，
broker 子模块固定 `dacb66341f0d09dadc3b282e88b46a2fb34c5f29`（0.6.0）。
没有重启、升级、取消或提交 B300-M3 GPU 作业；没有更改 evaluator/workload。
本轮实现是 `0.17.0.dev0`，尚未发布或部署。

## B300-M3 问题：观察与解释分开

1. **历史 stale foreign（9 月 23 日）。** 既有实验记录报告 8 张卡显示旧 foreign
   PID，而独立设备查询为空；重启回执保留旧/新 instance，重启后 8 卡 idle。
   回执位于 `kersor-portfolio-b300-m3-20260923-01a0cc51/broker-restart-result.json`。
   当前源码显示 GPU probe 的 `nvidia-smi` 子进程没有超时，`snapshot.updated_at`
   在响应时生成，不是 probe 时间。它们是可导致观察失真的具体缺口，但没有历史
   traceback 证明当时恰好是哪一个缺口触发；不把推断写成已证实根因。
2. **本次限定卡 FIFO 阻塞（10 月 3 日 14:40:53，Asia/Shanghai）。**
   队首 `gpuq-de905d0fcf83` 与第二项 `gpuq-c3f30a65aa52` 的 admission 都限定
   `[0]`；正在 GPU 0 上执行的 `gpuq-53eab8e8c2ef` 也限定 `[0]`。
   后续 `gpuq-43f0d46c03a8`、`gpuq-8d66c09a2d12`、`gpuq-15dbb556d55d`
   的 scope 为 `null`。当前实现只尝试队首，无法分配就停止本轮调度。
   因此“其他卡空闲但不限卡工作也等待”符合当前严格 FIFO 合同，是利用率代价，
   不是本次已证明的 scheduler 死锁。改变它需要先决定是否允许越过队首。
3. **CPU 工作占租约。** 历史组合评测曾在 GPU 作业内重复编译 C++17/C++20；
   CPU 预编译后才进入设备配对测试解决了该实验的问题。已有 `local` 阶段与
   lease lifecycle 足够表达正确做法，无需再加入自动 suspend/unlock/resume。
4. **诊断路径不匹配。** 此节点直接用 broker；旧诊断实现要求 daemon，且只从
   daemon run 推导 attention，遗漏纯 broker 的长排队。本轮已补齐显式直接入口。

14:45:30 的后续只读验证通过 SSH Unix-socket 转发运行本轮真实 CLI，返回
`scope=broker`、exit 0、4 running / 2 queued、4 exclusive / 4 idle。
这是有时间戳的 status 观察；既不是“节点永远正常”，也不是 GPU probe 新鲜度、
算子正确性、性能或新版本部署验收。

## 下一轮应解决的具体事项

1. **先统一 broker 源码与部署归属。** 找回/核实 `807aea5` 对应源码，将 GPU scope
   能力与主线 scheduler hardening 合并到一个可复现 successor。重新验证 CLI、
   receipt、调度与 cleanup 后，另行安排生产升级。不用 package version 代替
   source closure，也不直接把正在跑的目录当成源码主线。
2. **给 GPU probe 加有限等待并记录真实采样时间。** probe 卡住时应终止并回收
   probe 子进程，状态 fail closed；调度异常不得悄悄丢失整个循环。通过阻塞 probe
   和单次 scheduler 异常的故障注入验证恢复。需要在统一后的 broker 源码完成，
   不能只在 GPU Infra 投影里伪造一个 heartbeat。
3. **明确 GPU scope 的用途与 FIFO 代价。** 固定卡复测/诊断可以保留 `[0]`；普通
   可迁移作业应避免意外继承固定卡约束。若要 backfill，先确定公平性/饥饿边界，
   然后修改唯一 broker 的策略；不在 GPU Infra 增加第二个队列或重试器。
4. **保持安装入口一致。** 本机 Skill 链接仍指向旧 checkout，本轮未切换共享配置。
   发布 successor 后再选择正式 checkout/安装版本，避免复制 Skill 或依赖会移动
   的实验目录。旧 checkout 与历史证据已保留。
