## Contract

Before `service-start` creates deployment state, it now requires:

- live broker status declaring semantic version 0.6 or newer;
- a non-empty broker instance identity;
- no broker probe error;
- the configured gpu-run client to parse `--estimate unknown`;
- the client help surface to expose `--receipt-out`.

The client check invokes only `gpu-run --estimate unknown --help`; it cannot
connect to a broker or submit a job. Any failure occurs before deployment
directory, state, event, log, broker job, or GPU request creation.

`service-preflight` exposes the exact same check as read-only
`kernelinfra.service-preflight.v1`. The result records checked service identity,
broker socket/version/instance, gpu-run path, and the two required capability
booleans. It is not an authorization token: `service-start` reruns the same
function at acceptance.
