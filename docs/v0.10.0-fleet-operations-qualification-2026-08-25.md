## Remote observation contract

`fleet-status`, `fleet-wait`, `fleet-cancel`, and `fleet-frontier` optionally
create `kernelinfra.remote-observation.v1` with:

- catalog path/digest;
- immutable node/run locator;
- operation;
- timestamp;
- exact response or error;
- status `ok` or `unknown`;
- canonical observation SHA-256.

Existing outputs are never overwritten. Locator, route, catalog, remote bundle,
remote run, and frontier task identities are validated before use.

`fleet-wait` treats remote exit 3 as a valid nonterminal observation rather than
a transport error. Remote timeout/SSH/daemon failures are unknown and cannot
change node-owned lifecycle state.
