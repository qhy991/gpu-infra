## Snapshot contract

`fleet-snapshot` accepts 1–256 submitted route receipts. It validates and
deduplicates the complete set before SSH, then performs at most 16 concurrent
fixed-node status calls. Every successful response must match the route's run,
task, and candidate identity.

The create-only `kernelinfra.fleet-snapshot.v1` view contains:

- the checked catalog path;
- exact route path and existing route-receipt identity;
- immutable `(node_id, run_id)` locator;
- exact remote state response or error;
- `ok` or `unknown` status per route;
- derived total/ok/unknown/terminal/nonterminal/state counts.

It does not probe for a replacement node, submit, wait, retry, fail over,
cancel, fetch artifacts, or update a run. No new digest is generated; existing
catalog/route/run identities are reused.
