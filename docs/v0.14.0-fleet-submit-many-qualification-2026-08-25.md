## Contract

`fleet-submit-many` accepts one task and 1–64 candidate directories. Before any
SSH it snapshots and validates every task/candidate bundle, verifies the task
did not change during preflight, and rejects duplicate task/candidate content.

It then probes the complete fleet once. For every candidate, projected-load
planning considers:

- observed broker queue length after the planned assignment;
- remaining idle GPU count after the planned assignment;
- active run count plus already planned items;
- node id as deterministic final tie-break.

This plan is not a reservation. At most eight transports run concurrently and
each selected daemon/broker remains authoritative. Every item writes a normal
`kernelinfra.route-receipt.v1`; the create-only output also stores the exact
catalog, the one shared probe, and a no-digest
`kernelinfra.fleet-batch-summary.v1` derived index.

Remote partial success is never retried on another node, rolled back, or
cancelled because a sibling fails. A missing final `summary.json` indicates an
interrupted client; any already written route receipts remain authoritative.
