## Contract

`fleet-collect` accepts 1–64 unique submitted route receipts and an optional
current endpoint map. It first performs one concurrent, identity-checked fleet
snapshot, then revalidates every route and endpoint before creating output.

Only node-owned terminal states are fetched. Completed, rejected, infra-error,
cancelled, and interrupted runs are all evidence; collection does not reinterpret
their validity. At most eight artifact fetches run concurrently.

The create-only collection stores checked catalog and route copies, the exact
snapshot, independent `kernelinfra.artifact-mirror.v2` directories, and one
no-digest `kernelinfra.fleet-collection.v1` summary. Item status is:

- `mirrored`: terminal evidence fetched and validated;
- `nonterminal`: running/queued/etc., deliberately not waited or fetched;
- `unknown`: node/daemon/identity could not be observed;
- `fetch_failed`: terminal state was known but artifact transport/install failed.

Exit 0 means every route was terminal and mirrored. Exit 3 means nonterminal
work remains with no unknown/fetch failure. Exit 1 means unknown or fetch
failure. Successful sibling mirrors are never removed. The command does not
poll, wait, cancel, retry, fail over, route, submit, or update a remote run.
